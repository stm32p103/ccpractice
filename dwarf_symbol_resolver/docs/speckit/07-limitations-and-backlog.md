# 既知の制約・未検証事項と、機能追加の候補

`/speckit-specify` の題材として使えるよう、優先度の目安を付けています (高・中・低)。

## 未検証事項

| 項目 | 内容 | 確かめ方 |
|---|---|---|
| Green Hills (RH850) | 想定している本命の処理系だが、実物の ELF で未確認 | `dwarf-adapter` スキルで適合と検証を行う |
| 最適化ありのビルド | 検証は `-O0` だけ。最適化で変数が消える・ロケーションリストになる場合の挙動は未確認 | 設定のバリアントに `-O2` などを足して検証する |
| 複数の翻訳単位 | 検証用のサンプルは 1 ファイル。同名の static が複数のファイルにある場合の区別は、単体では確認したが検証ツールの対象外 | `verification/` に 2 つ目の .c を足す (検証ツールの拡張が必要) |
| 大きな ELF での性能 | 起動時に全 CU を走査して変数の索引を作る。実製品規模での時間は未計測 | 実製品の ELF で計測する |

## 既知の制約

| 制約 | 影響 | 回避策 |
|---|---|---|
| リトルエンディアンのみ | ビッグエンディアンのビットフィールドは `ResolveError` | 07 の候補 B |
| 変数のアドレスは `DW_OP_addr` のみ | `DW_OP_addrx` やロケーションリストでは、ELF シンボル表から補う (補えなければエラー) | シンボル表があれば多くは解決できる |
| インデックスに `sizeof`・キャストは使えない | `ResolveError` | 07 の候補 C |
| 関数内 static のシンボル名の照合は GCC の規則 (`name.N`) が既定 | 処理系が違うと照合できない (DWARF のアドレスがあれば解決はできる) | `ElfSymtabSource(local_static_pattern=...)` で指定 |
| 列挙子の索引は名前だけで持つ | 別のファイルに同名で値の違う列挙子があると、後から読んだ方になる | 現状は注意事項に出ない |
| 配列全体・構造体全体の指定 | アドレスと全体のサイズは返るが、`encoding` は `None` | 要素・メンバを指定する |
| 自動テストがない | 検証ツール (処理系が必要) とカタログ検査だけで、純粋な Python の単体テストがない | 07 の候補 A |

## 機能追加の候補

### A. 単体テストの整備 (高)

処理系がなくても回るテスト (pytest) を用意する。
- 左辺値の文法 (`parse_lvalue`)、コメント候補の抽出 (`extract_comments`)、数値の評価 (`eval_fraction`)
- 検証済みの ELF (`verification/results/arm_gcc/*/app.elf`) を使った回帰テスト (`result.md` の表との一致)
- 理由: 保守担当が変わっても、壊したことにすぐ気付けるようにする。現状は arm-none-eabi-gcc がないと何も確かめられない

### B. ビッグエンディアン対応 (中)

`DwarfSource.bitfield_pos` と `Resolved.mask` の意味 (現在はリトルエンディアンで整数化した値に対するマスク) を、
ビッグエンディアンでも一意になるよう定義し直す。仕様 (02 の FR-05) の更新が必要。

### C. インデックス式の拡張 (中)

`sizeof(型)` / `sizeof(式)` と単純なキャスト (`(int)`) を、DWARF の型情報で評価する。

### D. 利用者向けのコマンドラインツール (中)

`examples/export_monitor_csv.py` を正式なコマンド (`dsr-export` など) にする。
処理系の設定ファイル (`verification/toolchains/*.json` と同じ形式) からプリプロセスのコマンドと `DebugInfoSource` を選べるようにする。
出力形式は利用者ごとに違うため、プラグイン (出力の変換関数) で差し替えられる形にする。

### E. 処理系の自動判別 (低)

DWARF の `DW_AT_producer` から処理系を判別し、`DebugInfoSource` のクラスを自動で選ぶ。

### F. 検証ツールの拡張 (低)

複数の翻訳単位、最適化ありのビルド、関数内 static の正解の取得 (関数内に `&` を出力するコードを差し込む) に対応する。
