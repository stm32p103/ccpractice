# 実現したいこと
エージェント・スキル作成の練習のお題として以下のような業務を補佐するエージェントを作りたい

# 前提
* 本プロジェクトの内容は、プラグインとしてGitHub上で開発し、配布できるようにしたい(以降本プラグインと呼ぶ)
* 本プロジェクトでは、本プラグインをSpecKitに基づき要件を整理し、エージェント・スキルなどを構築する
* エージェント・スキルの構成を提示する際は、トークン消費量と、エージェント・スキルと読み書きする文書の関係・GitHubやAIのフックで実行するスクリプトなどを可視化すること
  * 文書は時間がたつごとに肥大化することを留意し、将来にわたって軽量に扱える運用を提案すること
  * 例えば、「決定事項が決定したら、完了済ファイルに移行し以後は指示がない限り読みにいかない」とか、単純なファイルの加工はAIではなくスクリプトで実行するなど
* Claude/Github Copilot どちらでも動作すること
* センシティブなデータは、利用者の指示であっても絶対に外部に漏らしてはならない(検索やリポジトリ、Issueへの書き込みなどが該当)

# 利用者
* 利用者はある業務に携わるチームのメンバー全員と、チームのマネージャーと、チームへ業務を依頼する「依頼者」を想定する
  * 対象のチームは、別のチームから依頼を受けて、作業を実施したり、設計・実装・評価して納めるなどのエンジニアリングを行う

# 実現したいこと
## 非定型業務の依頼の受付
### 目的
チームへの依頼を管理下に置くための入り口として、「依頼の受付」を行う。
Issueをチーム外との唯一の窓口とし、依頼元とのやり取りを必ずIssueで行い、納期や実施事項を合意したり、必要な情報の提供を依頼と受領をするので、
Issue上のやり取りを要約し、メンバーが取り組み、やることの取りこぼしが発生しないようにしたい。

### 内容
* GitHubのIssueで特定のタグ(「依頼」のような形)は「チームへの依頼」と扱う
* 利用者が任意のタイミングで未受付の依頼をリストアップすることを要求したら、「依頼」タグがあり「受付済」のような受け付けたことが分かるタグがないIssueのリンクをMarkdownにまとめる
  * 本機能は、トークン節約のために、Pythonスクリプトで実現し、利用者が自身の資格情報のもと実行できるようにしてほしい
  * AIへの指示があったらPythonスクリプトを実行できるようにしてほしい
* 受付フォロー
  * 定例会のトピック作成(後述)や、やることの問い合わせ(後述)にあたって、未受付の依頼があれば先に提示してほしい
* 受付済の依頼は受付済の依頼リスト(Markdown)に追記してほしい
  * 本処理はスクリプトで実現してほしい
* 完了(Issueのクローズ)したものは、完了リストに追記してほしい
  * 本処理はスクリプトで実現してほしい
* 利用者は依頼者とのやり取りをIssueで行い、ある程度まとまった段階で本エージェントにメンションし「受付」を指示するので、それをトリガにIssueとコメントを読み込む
  * 読み込んだ内容を要約し、依頼ファイルとしてリポジトリに保存する
    * 依頼のキーワードが過去の依頼・対応のサマリに合致するものがあれば、「対応案」に過去の対応案に、該当する依頼と対応のリンクを載せる
      * 依頼がクローズしたら、キーワードと依頼・対応のサマリを作成する(トークン消費が大きくならないような工夫が欲しい)
  * 取り込む際に、納期や担当者など、いくつかの観点(今後使いながら観点を追加していきたい)が不足していたら利用者に確認を促し、指示されたらIssueで問い合わせること
  * 依頼と課題は、AIと人がチャットを通して要件を詰めたり、課題の書き出し、判断の記録をするのに使うため、Markdownでまとめつつ、機械的な集計・関連性の表現を表せるよう、JSONないしYAML(Pythonで型安全で扱いやすいほう)で表現したい
  * 依頼の元となるIssueが変更されたり、コメントが追加されていないかチェックしたい
    * 本処理はスクリプトで実現してほしい
    * 利用者が対象のIssueでエージェントへメンションし、受付を指示したラ依頼ファイルを更新する
