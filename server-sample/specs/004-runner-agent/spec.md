# Feature Specification: ランナーエージェント — 外部ツールの実行

**Feature Branch**: `004-runner-agent`(現在のブランチは `job_service`。spec ディレクトリ名とブランチ名は独立)

**Created**: 2026-11-22

**Status**: Draft

**Input**: User description: "各 Windows PC 上で常駐し、コアからジョブを受け取り、外部ツールとして実行して結果を報告するエージェントを作る。特定のツールや用途を知らず、エグゼキュータという差し込み部品を通じて用途ごとの実行を行う。ランナーからサーバーへの接続のみ(着信接続は不要)。"(入力の全文: `inputs/06-specify-004-runner-agent.md`)

## ユビキタス言語

- **ランナーエージェント**: ランナー PC 上の常駐プログラム。
- **エグゼキュータ(Executor)**: 1 件のジョブを外部ツールとして実行する、用途ごとの部品。ジョブの payload を解釈できる唯一の部品。
- **ランナープロトコル**: エージェントとコア API の間の契約(取得・生存通知・ログ送信・結果報告・中断指示)。
- **リース**: ジョブの貸し出し。生存通知で延長され、切れると別の扱いになる(002)。
- **作業フォルダ**: ジョブごとに新規作成し、終了後に削除する専用のフォルダ。外部ツールの作業ディレクトリになる。
- **プロファイル**: 用途固有の部品の一式(最初の用途は equipment-check)。エージェント本体の外に置く。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ジョブを取得し、実行して、結果を報告する (Priority: P1)

ランナーの運用者として、ランナー PC にエージェントを常駐させ、自分の PC が実行できる条件(能力)を登録しておけば、
条件に合うジョブが待機列に来たとき、エージェントが自動で 1 件取得し、外部ツールとして実行し、結果をコアへ報告してほしい。
待ち受けはサーバーからの着信ではなく、エージェントからの問い合わせで行う。

**Why this priority**: 取得 → 実行 → 報告の一巡が動かなければ、基盤全体が価値を持たない。最小の価値の単位(MVP)である。

**Independent Test**: 偽のコアと、スリープするだけの偽のエグゼキュータで、能力の登録 → ジョブの取得 → 実行 → 成功の報告が一巡することを確認する。

**Acceptance Scenarios**:

1. **Given** 能力を登録済みのエージェントと、条件に合うジョブが待機列にある状態, **When** エージェントが問い合わせる, **Then** ジョブを 1 件だけ取得し、対応するエグゼキュータで実行し、結果(成功/失敗、終了コード、成果物の参照)をコアへ報告する。
2. **Given** 条件に合うジョブがない状態, **When** エージェントが問い合わせる, **Then** ジョブは取得されず、エージェントは待機して次の問い合わせを行う(サーバーからの着信は受けない)。
3. **Given** ジョブの実行中, **When** 生存通知の間隔が経過する, **Then** エージェントは生存通知を送り、リースが延長される。
4. **Given** 実行中のジョブ, **When** 外部ツールが標準出力・標準エラーへ書く, **Then** ログがコアへ逐次送信され、WebUI で参照できる。
5. **Given** ジョブ種別(job_type)に対応するエグゼキュータが設定にない, **When** そのジョブを取得した, **Then** 実行せず、理由付きの失敗として報告する(外部ツールは起動しない)。

---

### User Story 2 - 機密情報を持ち出さない (Priority: P1)

セキュリティ責任者として、ジョブを実行しても、作業フォルダ外のファイル・環境変数・他のサービスの情報が、
外部へ送信されないこと、ログや成果物にも現れないことを、テストで確認できるようにしたい(憲章 S1〜S6、書き出し台帳 E4〜E8)。

**Why this priority**: 憲章の最重要原則(NON-NEGOTIABLE)。これを満たさない実行は許可できないため、P1 とする。

**Independent Test**: テスト用のダミーの秘密(作業フォルダ外のファイルと環境変数)を読もうとするツールを実行し、
ツールの出力・成果物・ログに内容が現れないこと、送信を記録する偽のサーバーで台帳にない通信が 0 件であることを確認する。

**Acceptance Scenarios**:

1. **Given** 作業フォルダ外のファイルと環境変数にダミーの秘密がある状態, **When** それらを読もうとするツールを実行する, **Then** ツールの出力・成果物・ログのいずれにもダミーの秘密が現れない。
2. **Given** エージェントの環境に任意の環境変数がある状態, **When** 外部ツールを起動する, **Then** ツールの環境変数は空の状態から許可リストの変数だけで組み立てられ、親の環境を継承しない。
3. **Given** ジョブの入力に `..`・絶対パス・シンボリックリンク・ジャンクションを含むパスがある, **When** 実行を始める, **Then** 正規化の上で拒否され、監査ログに記録される(外部ツールは起動しない)。
4. **Given** 送信を記録する偽のサーバー, **When** ジョブの一巡(取得・実行・ログ・結果・成果物)を行う, **Then** 台帳(E4〜E7)にない宛先・内容への通信が 0 件である。
5. **Given** ログに既知の機密パターン(トークン等)が含まれる, **When** ログを送信する, **Then** パターンがマスクされ、マスクの発動が監査ログに記録される。
6. **Given** ジョブ定義で成果物の出力パターンを明示している, **When** 成果物を収集する, **Then** 作業フォルダ内の、パターンに一致するものだけが収集される。

### User Story 3 - ジョブを中断・タイムアウトで確実に止める (Priority: P2)

権限を持つ利用者として、実行中のジョブを中断したとき、外部ツールが起動した子プロセスも含めて確実に止まり、
状態が「中断」と報告されてほしい。タイムアウトを超えたジョブも、エージェントが止めて「失敗(タイムアウト)」と報告してほしい。

**Why this priority**: 止められないジョブは、共用のランナーを占有し続ける。運用の前提となるが、取得 → 実行 → 報告より後でよい。

**Independent Test**: 子プロセスを起動する偽のエグゼキュータで、中断指示とタイムアウトのそれぞれの後に、子プロセスを含めて全プロセスが残らないことを確認する。

**Acceptance Scenarios**:

1. **Given** 実行中のジョブ(子プロセスあり), **When** 中断指示を受ける, **Then** 起動したプロセスをプロセスツリーごと停止し、状態「中断」を報告する。
2. **Given** タイムアウトの設定があるジョブ, **When** 実行時間がタイムアウトを超える, **Then** エージェントがプロセスツリーごと停止し、「失敗(タイムアウト)」を報告する。
3. **Given** 中断またはタイムアウトで停止した, **When** 後始末を行う, **Then** 作業フォルダが削除され、取得資格が破棄される。

---

### User Story 4 - サーバーや PC の障害から自動で復帰する (Priority: P2)

ランナーの運用者として、エージェントが Windows サービスとして動作し、PC の再起動後に自動で復帰してほしい。
サーバーに到達できない間も、実行中のジョブは継続し、復旧後に結果が報告されてほしい。

**Why this priority**: 無人運用の前提。一巡が動いた後に、実運用に必要な堅牢性として加える。

**Independent Test**: 実行中に偽のコアを一時停止し、ジョブが完了して復旧後に結果が報告されること、およびサービスの再起動後にエージェントが再登録して問い合わせを再開することを確認する。

**Acceptance Scenarios**:

1. **Given** 実行中のジョブ, **When** サーバーに到達できなくなる, **Then** ジョブは継続し、完了後、復旧した時点で結果が報告される。
2. **Given** PC が再起動された, **When** OS が起動する, **Then** エージェントのサービスが自動で起動し、能力を再登録して問い合わせを再開する。
3. **Given** サーバーに到達できない間にジョブが終了した, **When** 復旧する, **Then** 結果(ログの未送信分を含む)が失われずに報告される。

---

### User Story 5 - 用途ごとの実行を、設定の追加だけで足す (Priority: P2)

開発者として、新しい用途(別のツール)に対応するとき、エージェントの中核を変更せず、エグゼキュータを追加して
ジョブ種別と設定で対応付けるだけにしたい。最初の用途として、プロファイル equipment-check のエグゼキュータ
(チェックツールの起動、引数と作業ディレクトリの組み立て、結果の解釈)を用意する。

**Why this priority**: 汎用性(憲章 原則 1、3)の合格条件。ただし最初の用途の動作確認は、一巡の後でよい。

**Independent Test**: コアなしで、エグゼキュータを単体で試験できること。偽のコアで、エージェントを試験できること。
エージェントのコードにチェックツール固有の語や import がないことを、機械的に検査できること。

**Acceptance Scenarios**:

1. **Given** 新しいエグゼキュータと、ジョブ種別との対応の設定, **When** エージェントを起動する, **Then** エージェントの中核を変更せずに、そのジョブ種別を実行できる。
2. **Given** エージェントのコード, **When** 依存と語彙を検査する, **Then** チェックツール固有の語や import が含まれない。
3. **Given** equipment-check のエグゼキュータ, **When** コアなしで単体試験する, **Then** 引数・作業ディレクトリの組み立てと結果の解釈が検証できる。

---

### User Story 6 - 実行できるジョブを制限する (Priority: P2)

セキュリティ責任者として、エージェントが低権限のアカウントで実行され、実行できるジョブ(ソースリポジトリ)が
許可リストで制限されていてほしい。

**Why this priority**: S3(既定は拒否)・S5(信頼できるものだけを実行する)の実装。

**Independent Test**: 許可リスト外のリポジトリのジョブを取得させ、実行されずに拒否されることを確認する。サービスの実行アカウントが低権限であることを確認する。

**Acceptance Scenarios**:

1. **Given** 許可リストにないソースリポジトリのジョブ, **When** 取得した, **Then** 実行せず、理由付きの失敗として報告し、監査ログに記録する。
2. **Given** エージェントのサービス, **When** 実行アカウントを確認する, **Then** 専用の低権限アカウントであり、作業フォルダ以外への読み取りの権限を持たない。

---

### Edge Cases

- 実行中にエージェントのサービスが再起動された場合、起動した外部ツールの扱いと、リースの扱いはどうなるか(リース切れのジョブは失敗として確定する。FR-024)。
- サーバーへ到達できない時間が、リースの長さを超えた場合、実行中のジョブはどうなるか(継続して結果を報告しようとするが、リース切れで失敗が確定済みのため、結果は受理されない。エージェントは報告の拒否を記録し、作業フォルダと成果物の後始末を行う)。
- 作業フォルダの作成・削除に失敗した場合(ディスクの空き不足、他のプロセスによるロック)は、失敗として報告し、残った作業フォルダを次の起動時に掃除する。
- 外部ツールが大量のログを出した場合は、台帳の「ログの量の制限」に従い、上限を超えた分を切り詰める(切り詰めた事実を記録する)。
- 外部ツールが終了コードを返さず、またはプロセスツリーから離脱したプロセスを残した場合も、中断・タイムアウトの停止で漏れなく止める。
- 同じジョブの中断指示と完了が競合した場合は、先に確定した状態を優先し、後の報告は拒否される(001 の不変条件に従う)。
- エグゼキュータが例外を起こした場合は、エージェント全体を停止せず、そのジョブを理由付きの失敗として報告する。
- ツールが機材の異常を伝えようとした場合の、ツールからエージェントへの伝え方(Assumptions 参照)。

## Requirements *(mandatory)*

### Functional Requirements

#### 取得・実行・報告

- **FR-001**: エージェントは、能力(自分が実行できる条件)を登録した上で、コア API に認証して接続し、条件に合うジョブを 1 件取得しなければならない。待ち受けは、サーバーからの着信ではなく問い合わせで行う。
- **FR-002**: エージェントは、ジョブの実行中、定期的に生存通知を送り、リースを延長しなければならない。
- **FR-003**: エグゼキュータは、ジョブの payload を受け取り、外部ツールを起動しなければならない。エグゼキュータは、ジョブ種別(job_type)ごとに設定で対応付けられる。対応のないジョブ種別は、実行せず失敗として報告する。
- **FR-004**: 実行中のログは、エージェントからコアへ逐次送信され、WebUI で参照できなければならない。
- **FR-005**: エージェントは、結果(成功/失敗、終了コード、成果物の参照)をコアへ報告しなければならない。成果物の本体はコアへ送らず、保存先(FR-025)へ置き、参照(所在)だけを報告する。
- **FR-006**: エージェントは、中断指示を受けたら、起動したプロセスをプロセスツリーごと停止し、状態を「中断」で報告しなければならない。
- **FR-007**: エージェントは、タイムアウトを超えたジョブを停止し、「失敗(タイムアウト)」で報告しなければならない。
- **FR-024**: リース切れのジョブは、待機列へ戻さず、失敗として確定する(自動で再実行しない)。やり直しは利用者が再提出で行う(憲章 原則 5)。エージェントは、リース切れで失敗が確定したジョブの結果の報告が拒否されたとき、拒否を記録し、実行中であればプロセスツリーごと停止し、作業フォルダを削除する。副作用のあるツールの再実行は、自動では行わない。
- **FR-025**: 成果物の本体は、コア API へ送らず、設定で指定した保存先へ置き、コア API へは参照(UNC パスまたは URL)だけを通知しなければならない。保存先は、次のいずれかとし、設定で選ぶ。
  - ランナー自身の PC の共有フォルダ(参照は UNC パス)
  - 大容量ストレージ(参照は URL)
  保存先(共有フォルダの場合は「実行結果」フォルダ)は、**ランナーごとに設定で指定できる**。台帳 E6 に具体化済み(2026-11-22)で、設定した 1 か所以外へは書かない。参照には、ログの本文・成果物の中身・作業フォルダ外のパスを含めない。**保存先のアクセス権の設定は、本システムの範囲外**とする(ジョブの依頼者の所属するチーム全体で参照できるように、運用で設定する)。保存先の容量の上限と保持期間は設定で与える。
- **FR-026**: ソース(リビジョン)の取得は、エージェントが担当する。エージェントは、許可リストのリポジトリについて、コア API 経由で得た短命・読み取り専用の取得資格で取得し、作業フォルダへ展開してからエグゼキュータへ渡す。取得資格はエグゼキュータと外部ツールへ渡さず、ジョブ終了で破棄する(台帳 E7)。

#### 運用

- **FR-008**: エージェントは Windows サービスとして動作し、PC の再起動後に自動で復帰しなければならない。
- **FR-009**: エージェントは、サーバーに到達できない間も、実行中のジョブを継続し、復旧後に結果を報告しなければならない。
- **FR-010**: エージェントは、低権限のアカウントでジョブを実行しなければならない。実行できるジョブ(ソースリポジトリ)は許可リストで制限される。
- **FR-011**: エグゼキュータの追加は、エージェントの中核を変更せず、設定で行えなければならない。動的なプラグイン読み込み機構は設けない。
- **FR-012**: コアなしでエグゼキュータを単体試験でき、偽のコアでエージェントを試験できなければならない。

#### 機密保護(最重要。憲章 S1〜S6、書き出し台帳 13-security-egress に従う)

- **FR-013**: エージェントは、ジョブごとに専用の作業フォルダを新規作成し、ジョブ終了後(成功・失敗・中断・タイムアウトのいずれでも)に削除しなければならない。外部ツールは作業フォルダを作業ディレクトリとして起動される。
- **FR-014**: エージェントと外部ツールは、作業フォルダ外のファイル・環境変数・他のサービスの情報を、外部に送信してはならない。
- **FR-015**: 外部ツールの環境変数は、空の状態から、許可リストの変数だけで組み立てなければならない(親プロセスの環境を継承しない)。
- **FR-016**: ジョブの入力値は、シェルを介さず引数配列として渡さなければならない。作業フォルダ外を指すパス(`..`、絶対パス、シンボリックリンク、ジャンクション)は、正規化の上で拒否し、監査ログに記録しなければならない。
- **FR-017**: エージェントが外部へ書き出すものは、次に限る(台帳の E4〜E7)。これ以外は書き出さない。
  - コア API へ: 能力の登録(許可した項目のみ)、生存通知、ジョブの状態、ログ(機密パターンをマスクしたもの)、結果、成果物(E4〜E6)。
  - ソース取得先へ: 取得要求(取得のみ)(E7。取得はエージェントが担当する。FR-026)。
  - 成果物の保存先へ: 成果物の本体(E6。FR-025)。
- **FR-018**: 成果物として収集するのは、作業フォルダ内の、ジョブ定義で明示した出力パターンに一致するものだけでなければならない。
- **FR-019**: エージェントは Git にコミット/プッシュしてはならない。外部ツールの外向き通信は、既定で許可しない(必要な通信は台帳に追加して許可する。E8)。
- **FR-020**: エージェントはテレメトリ・解析を送信してはならない。外部の配信資産を読み込んではならない。
- **FR-021**: エージェントは、作業フォルダ外へのアクセスの拒否、ログのマスクの発動、許可リスト外のジョブの拒否、書き出しを、監査ログに記録しなければならない。記録に、ログの本文・環境変数の値・資格情報を含めてはならない。

#### 最初の用途(プロファイル equipment-check)

- **FR-022**: 用途固有の部品として、equipment-check のエグゼキュータ(チェックツールの起動、引数と作業ディレクトリの組み立て、結果の解釈)を、エージェント本体の外に置かなければならない。エージェント本体は、チェックツール固有の知識(語・import)を持ってはならない。
- **FR-023**: 実行中の PC 内のツールは、機材の異常と回復を、ローカルの手段でエージェントへ伝えられなければならない。エージェントだけが、これをコア API へ送る(ツールから PC の外へは送らない。E8)。申告の内容は、002 の規則(短い説明の長さの上限、作業フォルダ外の情報を含めない)に従う。故障の自動検知は行わない(002 で決定済み)。

### Key Entities

- **ランナーエージェント**: ランナー PC 上の常駐プログラム。能力の登録、ジョブの取得、実行の管理、報告を担う。用途固有の知識を持たない。
- **エグゼキュータ**: ジョブ種別ごとの、1 件のジョブを外部ツールとして実行する部品。payload の解釈、起動、結果の解釈を担う。
- **ジョブ種別とエグゼキュータの対応(設定)**: どのジョブ種別をどのエグゼキュータで実行するかの対応。起動時の設定で与える。
- **実行(Execution)**: エージェントが 1 件のジョブについて行う実行の記録。作業フォルダ、起動したプロセス、開始・終了、終了コード、停止の理由(中断・タイムアウト)を持つ。
- **作業フォルダ**: ジョブごとに新規作成・終了後に削除する専用フォルダ。
- **許可リスト**: 環境変数、実行できるソースリポジトリ、能力の申告項目などの許可。許可リスト外は拒否する。
- **ログのチャンク/成果物**: 外部ツールの出力と、出力パターンに一致する成果物。マスク・量の制限・パターン一致を経たものだけが送られる。
- **ランナープロトコル**: コア API との間の契約(003 で定義されたランナー向けの契約を使う)。

### Egress(外部への書き出し。憲章 S2)

台帳(`inputs/13-security-egress.md`)にある項目だけを扱う。追加はない。

| 台帳 | 送信元 → 出力先 | 内容 | 条件 |
|---|---|---|---|
| E4 | エージェント → コア API | 能力の登録、生存通知、ランナーの状態(異常と回復)、ジョブの状態 | 許可リストの項目のみ。異常の説明は長さの上限あり、作業フォルダ外の情報を含めない |
| E5 | エージェント → コア API | ジョブのログ | 機密パターンはマスク。量を制限 |
| E6 | エージェント → 成果物の保存先(ランナー自身の PC の共有フォルダ、または大容量ストレージ)。コア API へは参照(UNC パスまたは URL)だけ | 成果物の本体(保存先へ)、成果物の参照(コア API へ) | 作業フォルダ内の、出力パターンに一致するものだけ。**台帳の E6 の更新(保存先の具体化)とレビューを要する(FR-025)** |
| E7 | エージェント → ソース取得先 | 取得要求(取得のみ)、短命の取得資格 | 許可リストのリポジトリのみ。資格は短命・読み取り専用・ジョブ終了で破棄。取得はエージェントが担当し、エグゼキュータへ資格を渡さない(FR-026) |
| E8 | 外部ツール → なし | — | 外部通信は許可しない |
| E16 | コア API → エージェント(応答のみ) | ジョブの識別子・定義・リース・間隔 | 本 feature はこれを受け取る側。着信接続は持たない |

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 偽のエグゼキュータ(スリープするだけ)で、取得 → 実行 → 報告の一巡が、人手の介入なしに成功する。
- **SC-002**: 作業フォルダ外のファイル・環境変数のダミーの秘密を読もうとするツールを実行しても、ツールの出力・成果物・ログに、ダミーの秘密が 0 件(現れない)。
- **SC-003**: 送信を記録する偽のサーバーで、台帳にない宛先・内容への通信が、ジョブの一巡を通じて 0 件である。
- **SC-004**: 作業フォルダ外を指すパス(`..`、絶対パス、シンボリックリンク、ジャンクション)を含む入力が、100% 拒否され、そのすべてが監査ログに残る。
- **SC-005**: 中断指示またはタイムアウトの後、子プロセスを含めて、起動したプロセスが 0 件(残らない)。中断指示から停止までを、利用者が待てる短い時間(目安: 10 秒以内)に収める。
- **SC-006**: サーバーを一時的に停止しても、実行中のジョブは完了し、復旧後に結果が 1 回だけ報告される(失われない・重複しない)。
- **SC-007**: PC の再起動後、運用者の操作なしに、エージェントが自動で復帰し、次のジョブを取得できる。
- **SC-008**: 新しい用途のエグゼキュータの追加が、エージェントの中核の変更なしにできる。エージェントのコードにチェックツール固有の語や import が 0 件である。
- **SC-009**: 終了したジョブの作業フォルダが、成功・失敗・中断・タイムアウトのすべての終了で、残らない。

## Assumptions

- ログ本文は、成果物と異なり、従来どおりコア API へ送る(E5)。量の上限を超えた分は切り詰める。大容量の出力は、成果物として出力パターンで保存先へ置く。
- 成果物の保存先は、ランナーごとの設定(「実行結果」フォルダ、または大容量ストレージ)で指定する。具体的な宛先は運用で確定し、確定するまで、成果物の書き出しは無効とする(既定)。保存先のアクセス権(チーム全体での参照)の設定は、本システムの範囲外で、運用で行う。容量の上限・保持期間は設定で与える。
- コア API は 003 で定義されたランナー向けの契約を提供し、ランナーの登録・能力・リース・状態は 002、ジョブの待機列と状態は 001 に従う。本 feature はその利用側である。
- 生存通知の間隔(既定 30 秒)とリースの長さ(既定 3 分)は 002 の既定値に従い、コアからの応答で指示された間隔を使う。
- ツールからエージェントへの機材の異常の伝え方(FR-023)は、PC 内のローカルな手段(作業フォルダ内の、決まった名前の申告ファイル)とする。この方法は、設計(plan)で確定する。(clarify で見直してよい)
- ログの量の上限、タイムアウトの既定、許可リストの環境変数・リポジトリは、設定で与える。値の既定は plan で決める。
- ジョブの状態遷移の詳細、リース切れ・再実行・リトライの規則は、001・002 とあわせて別途定義する(スコープ外)。本 feature は、決定された規則に従って報告する側とする。
- 実行環境は Windows PC のみ(憲章 原則 7)。仮想化・コンテナは使えず、外部ツール自体が作業フォルダ外を読もうとする場合の限界は、OS の権限(専用アカウント、ACL)、ファイアウォールに頼る(憲章 S5)。実行するツールとリポジトリは、許可リストにより信頼できるものに限る。
- ランナー PC のセットアップの自動化(アカウントの作成、ファイアウォールの設定、サービスの登録)は本 feature の範囲外だが、憲章 原則 14 に従い、feature の完了までに、再現可能な構築スクリプトを段階的に拡張する。
- パイプライン記述言語・複数ステップの実行は作らない。1 ジョブ = 1 回の外部ツール実行とする(憲章 原則 4)。

### スコープ外

- ジョブの状態遷移の詳細、リース切れ・再実行・リトライの規則(001・002 とあわせて別途定義)
- 成果物の保存先のアクセス権の設定(ジョブの依頼者のチームへの読み取りの付与。運用で行う)
- ランナー PC のセットアップの自動化(憲章 原則 4)
- 機材の故障の自動検知(002 で決定済み)
