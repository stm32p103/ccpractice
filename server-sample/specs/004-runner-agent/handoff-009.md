# 009(環境構築)への引き継ぎ: ランナー PC の構築(ランナー用の構築スクリプト `setup-runner.ps1` の項目)

**根拠**: 憲章 原則 14、004 plan「他の feature への引き継ぎ」、research.md R4・R15〜R17・R20。
**本 feature(004)が定めるもの**: 項目と、構築後の検査(quickstart の V36〜V38)。**スクリプト自体は 009 が書く**。
**ランナー用の構築が未了のあいだは、004 の完了の定義(ランナー PC での再現)を満たせない**(下の「確認の項目」)。

## 構築の項目(冪等。ドライラン・事前確認・動作確認・撤去を備える。秘密は Windows の資格情報の保管機能)

| # | 項目 | 内容 | 検査 |
|---|---|---|---|
| 1 | 2 つのローカルアカウント | エージェント用(例: `svc-runner-agent`)と、ツール用の専用の低権限(例: `svc-runner-tool`)。ツール用は対話ログオン不可・グループは最小 | アカウントが存在し、ツール用が管理者でない |
| 2 | 作業フォルダの親・状態フォルダ | `work.root`(エージェントとツール用に変更の権限)、`state.dir`(エージェントだけ)。**ツール用のアカウントには、作業フォルダ以外への読み取りを ACL で与えない**。状態フォルダ・設定ファイルに、全員・Users の書き込みを与えない | V38、起動時の自己検査(`state.dir`・`work.root` の ACL) |
| 3 | 資格情報の保管 | ランナーのトークン(`core.runner_token_secret`)と、ツールのアカウントの資格(`launcher.tool_account_secret`。形式 `ユーザー名:パスワード`)を、**エージェントのアカウントの領域**に登録 | エージェント以外から読めない |
| 4 | ファイアウォール | ツールのアカウントの外向きの通信を**ユーザー単位の規則で遮断**(規則名 `JobRunnerToolEgressBlock`)。エージェントの外向きは、コア API・ソース取得先・(使うなら)成果物の保存先に限る | V37(規則がなければ `prod` は起動を拒否)、V38 |
| 5 | WinSW の登録 | `runner-service/winsw/agent.xml.template` を設定から埋める。自動(遅延)、失敗時の再起動、エージェントのアカウント | V18(再起動後の自動復帰) |
| 6 | `agent.toml` の雛形と検証 | `runner-service/config/agent.example.toml` を配置。`python -m job_runner_service --config <path> --check` で、設定の誤り(相対パス、`.bat` の登録、未知のエグゼキュータ、許可リストなど)を起動前に列挙して拒否 | V36 |
| 7 | 撤去 | サービス・アカウント・規則・資格情報・作業/状態フォルダの削除(成果物の保存先は削除しない) | — |

## 範囲外(004 の決定)

- **成果物の保存先(「実行結果」フォルダ・大容量ストレージ)のアクセス権の設定**: 本システムの範囲外。運用で、ジョブの依頼者のチーム全体に読み取りを与える。
  構築スクリプトは、保存先の ACL を作成・変更しない。エージェントのアカウントに**書き込み**の権限が必要なことだけを、エージェントの起動時の自己検査が確認する。
- 大容量ストレージを使う場合の資格の保管だけは、項目 3 に含める(`https_storage` の実装は、保存先の確定後)。
- ツールのアカウントには、「実行結果」フォルダへの権限を与えない運用とする(他のジョブの成果物をツールが読めないようにする。脅威モデル T-W6)。

## 確認の項目(ランナー PC。009 の基盤が整ったとき)

1. **スパイク(tasks T001)**: `runner-agent/spikes/logon_spike.py` を、構築した PC で実行する(サービスの文脈でも)。成立しない項目があれば plan を改定する。結果を `research.md` の R4 に追記する。
2. **V18**: PC の再起動後、エージェントが自動で起動し、能力を再登録して問い合わせを再開する。
3. **V36**: 設定の検証(ドライラン)が、誤りを起動前に拒否する。
4. **V37**: ファイアウォールの規則を外すと、`prod` のエージェントが起動を拒否する。
5. **V38(`pytest -m twoaccount`)**: `JOB_TEST_TOOL_ACCOUNT`・`JOB_TEST_SECRET_FILE`・`JOB_TEST_WORK_ROOT` を与えて、`runner-agent/tests/windows/test_us6_twoaccount.py` を実行する(ツールのアカウントで動く、作業フォルダ外が読めない、外向きの通信が遮断される)。
