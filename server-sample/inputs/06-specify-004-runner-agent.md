# /speckit.specify 入力(feature 004: runner-agent)

## 入力

```
# 機能: ランナーエージェント — 外部ツールの実行

## 背景と目的
各 Windows PC 上で常駐し、コアからジョブを受け取り、外部ツールとして実行して結果を報告するエージェントを作る。
特定のツールや用途を知らず、「エグゼキュータ」という差し込み部品を通じて、用途ごとの実行を行う。
ランナーからサーバーへの接続のみ(着信接続は不要)。

## ユビキタス言語
- ランナーエージェント: ランナー PC 上の常駐プログラム。
- エグゼキュータ(Executor): 1 件のジョブを外部ツールとして実行する、用途ごとの部品。ジョブの payload を解釈できる唯一の部品。
- ランナープロトコル: エージェントとコア API の間の契約(取得・生存通知・ログ送信・結果報告・中断指示)。
- リース: ジョブの貸し出し。生存通知で延長され、切れると別の扱いになる。

## 要件
- FR-1 エージェントは、能力(自分が実行できる条件)を登録した上で、コア API に認証して接続し、条件に合うジョブを 1 つ取得する(待ち受けは、サーバーからの着信ではなく問い合わせで行う)。
- FR-2 ジョブの実行中、定期的に生存通知を送りリースを延長する。
- FR-3 エグゼキュータは、ジョブの payload を受け取り、外部ツールを起動する。エグゼキュータは、ジョブ種別(job_type)ごとに設定で対応付けられる。
- FR-4 実行中のログは、エージェントからコアへ逐次送信され、WebUI で参照できる。
- FR-5 結果(成功/失敗、終了コード、成果物の参照)をコアへ報告する。成果物の保存方法は clarify で決める。
- FR-6 中断指示を受けたら、起動したプロセスをプロセスツリーごと停止し、状態を「中断」で報告する。
- FR-7 タイムアウトを超えたジョブは、エージェントが停止し「失敗(タイムアウト)」で報告する。
- FR-8 エージェントは Windows サービスとして動作し、PC 再起動後に自動で復帰する。
- FR-9 サーバーに到達できない間も、実行中のジョブは継続し、復旧後に結果を報告する。
- FR-10 実行は、低権限のアカウントで行う。実行できるジョブ(ソースリポジトリ)は許可リストで制限される。
- FR-11 エグゼキュータの追加は、エージェントの中核を変更せず、設定で行える(動的なプラグイン読み込み機構は設けない)。
- FR-12 コアなしでエグゼキュータを単体試験できる(偽のコアでエージェントを試験できる)。

## 機密保護(最重要。憲章の S1〜S6、書き出し台帳 13-security-egress に従う)
- FR-13 ジョブごとに専用の作業フォルダを新規作成し、ジョブ終了後に削除する。外部ツールは作業フォルダを作業ディレクトリとして起動される。
- FR-14 エージェントと外部ツールは、作業フォルダ外のファイル・環境変数・他のサービスの情報を、外部に送信しない。
- FR-15 外部ツールの環境変数は、空の状態から、許可リストの変数だけで組み立てる(親プロセスの環境を継承しない)。
- FR-16 ジョブの入力値は、シェルを介さず引数配列として渡す。作業フォルダ外を指すパス(.. 、絶対パス、シンボリックリンク、ジャンクション)は、正規化の上で拒否し、監査ログに記録する。
- FR-17 エージェントが外部へ書き出すものは、次に限る(台帳の E4〜E7)。これ以外は書き出さない。
  - コア API へ: 能力の登録(許可した項目のみ)、生存通知、ジョブの状態、ログ(機密パターンをマスクしたもの)、結果、成果物。
  - ソース取得先へ: 取得要求(取得のみ)。
- FR-18 成果物として収集するのは、作業フォルダ内の、ジョブ定義で明示した出力パターンに一致するものだけ。
- FR-19 エージェントは Git にコミット/プッシュしない。外部ツールの外向き通信は、既定で許可しない(必要な通信は台帳に追加して許可する)。
- FR-20 エージェントにテレメトリ・解析の送信はない。

## 受け入れ基準(機密保護)
- 作業フォルダ外のファイルと環境変数(例: テスト用のダミーの秘密)を読もうとするツールの出力・成果物・ログに、その内容が現れない。
- 送信を記録する偽のサーバーで、台帳にない宛先・内容への通信が 0 件であることを確認できる。
- ジョブ入力に `..` やシンボリックリンクを含むパスを与えると拒否され、監査ログに残る。

## 最初の用途(プロファイル equipment-check)
- 用途固有の部品として、エグゼキュータ(チェックツールの起動、引数と作業ディレクトリの組み立て、結果の解釈)を置く。
- エージェント本体にはチェックツール固有の知識を持たせない。

## 受け入れ基準(例)
- 偽のエグゼキュータ(スリープするだけ)で、取得 → 実行 → 報告が動く。
- 中断指示で、子プロセスを含めて停止する。
- サーバーを一時的に停止しても、実行中のジョブは完了し、復旧後に結果が報告される。
- エージェントのコードにチェックツール固有の語や import がない。

## スコープ外(別途詰める)
- ジョブの状態遷移の詳細、リース切れ・再実行・リトライの規則(002 とあわせて別途定義)
- ランナー PC のセットアップの自動化

## 未確定事項
- [NEEDS CLARIFICATION] リース切れ時のジョブの扱い(再キュー/失敗確定)と、副作用のあるツールの再実行可否
- [NEEDS CLARIFICATION] 成果物・ログの保存先(サーバー側/共有フォルダ)と容量
- [NEEDS CLARIFICATION] ソース(リビジョン)の取得の担当(エージェント/エグゼキュータ)と、取得資格の渡し方
- [NEEDS CLARIFICATION] 機材故障の検知と、ランナーの状態への反映 → 002 で決定済み(ツール → エージェント → コアの申告。故障の自動検知は行わない。002 spec の Clarifications)。PC 内のツールからエージェントへの伝え方は 004 で定める
```
