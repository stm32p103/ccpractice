# /speckit.specify 入力(feature 009: environment-setup)

各 feature は実装後に、個別に試行する。**各 feature の試行の前に、その feature に必要な構築・マイグレーションが
スクリプトで再現できる**ようにする(スクリプトは feature の実装に合わせて段階的に拡張する)。
最初の試行の前に、基盤(サーバーの構築、DB の導入とマイグレーションの枠組み、共通部品)を完成させる。

## 入力

```
# 機能: 環境構築の支援 — サーバー・ランナー(ワーカー)・DB マイグレーション

## 背景と目的
サーバーとランナー(ワーカー)の環境構築、DB のマイグレーションを、手順書の手作業ではなく、スクリプトで再現可能にする。
対象の環境は Windows PC のみ(仮想化・コンテナなし)。スクリプトは PowerShell で書く。
各 feature の実装後の試行に間に合うよう、feature の実装に合わせて段階的にスクリプトを提供する。
スクリプトは再利用可能とし、特定の用途(最初の用途: 評価機材のチェック)の語を含めない。用途固有の設定は、設定ファイルで与える。

## ユビキタス言語
- セットアップスクリプト: サーバーまたはランナーの環境を構築する、再実行できるスクリプト。
- 設定ファイル: 環境ごとの値(ホスト名、ポート、保存先、許可リスト等)を書くファイル。秘密情報は含めない。
- 事前確認(プリフライト): 実行前に、前提(OS の版、権限、空き容量、ポートの空き)を確認する処理。
- マイグレーション: DB のスキーマを、版を管理しながら更新すること。
- 動作確認(スモークテスト): 構築後に、主要な機能が動くことを確かめる簡易な試験。

## 要件
### 共通
- FR-1 スクリプトは Windows 標準の環境(Windows PowerShell 5.1 以降)で、追加の実行環境を前提とせずに動く。
- FR-2 スクリプトは再実行しても安全(冪等)で、実行前に変更内容を確認できる(ドライラン)。
- FR-3 実行の最初に事前確認を行い、満たさない場合は、理由と対処を示して停止する。
- FR-4 実行ログは、ローカルのファイルに記録する。ログに秘密情報(パスワード、トークン)を出力しない。
- FR-5 環境ごとの値は設定ファイルで与え、スクリプトに埋め込まない。設定ファイルの雛形と、値の検証(必須項目、形式)を提供する。
- FR-6 インストーラ・パッケージは、各製品の公式サイトから取得する。取得元のドメインは設定で許可リストとして固定し、HTTPS のみとする。
  版を固定し、公式が公開するハッシュまたは署名(Authenticode 等)で検証して、不一致なら停止する。取得は構築時のみで、構築後の稼働中は行わない。
- FR-7 アンインストール(撤去)と、構築後の動作確認(スモークテスト)を提供する。

### サーバー環境の構築
- FR-8 DB(PostgreSQL)の導入と設定: 専用の DB とロールを最小権限で作成し、接続を許可する範囲をイントラネットに限定する。
- FR-9 アプリケーション(コア API、連携部品、WebUI の静的資産)の配置と、Windows サービスへの登録(自動起動、異常時の再起動)。
- FR-10 秘密情報(DB のパスワード、サービス用の認証情報、連携の鍵)は、生成または入力を受け、Windows の資格情報の保管機能に保存する。
  サービスを実行するアカウントだけが読み出せる。画面・ログ・設定ファイルに出さない。
- FR-11 ファイアウォールの規則(受け入れる接続の限定)を設定する。
- FR-12 初期設定(管理者への所属グループ→ロールの対応、許可リポジトリ)を、設定ファイルから投入できる。

### ランナー(ワーカー)環境の構築
- FR-13 専用の低権限アカウントを作成し、作業フォルダのみに書き込み権限を与え、それ以外への読み取り権限を与えない(ACL)。
- FR-14 ランナーエージェントの配置と、Windows サービスへの登録(専用アカウントで実行、自動起動、異常時の再起動)。
- FR-15 Windows ファイアウォールで、外向き通信を許可先(コア API、ソース取得先)に限定する。
- FR-16 ランナーの登録(1 回限りの登録コードによる認証情報の払い出し)と、能力の設定ファイルからの登録。
- FR-17 外部ツールに渡す環境変数の許可リストと、エグゼキュータの設定を、設定ファイルから反映する。
- FR-18 構築後に、偽のジョブ(何もしないジョブ)でコア API との往復を確認する。

### DB マイグレーション
- FR-19 マイグレーションは、スクリプト 1 つで、現在の版の確認 → バックアップ → 適用 → 検証 まで行える。
- FR-20 適用前にバックアップを取得する。適用に失敗した場合は、バックアップからの復元手順を示す(戻しのマイグレーションの成功は前提としない)。
- FR-21 適用予定の変更を、適用前に一覧表示できる(ドライラン)。
- FR-22 稼働中のサービスの停止/再開と、実行中のジョブの扱い(待機させる/確認する)を、手順に含める。

### 機密保護(憲章の S1〜S6、書き出し台帳 13-security-egress に従う)
- FR-23 スクリプトは、環境変数・ファイル・資格情報を外部へ送信しない。書き出しは、台帳の E13(取得元からの取得のみ)と E14(ローカルのログのみ)に限る。
- FR-24 スクリプトは、テレメトリ・解析の送信を行わない。
- FR-25 秘密情報をファイルとして作る必要がある場合は、実行したアカウントと必要なサービスアカウントだけが読めるようにし、使用後に削除する。

### 段階的な提供と試行
- FR-26 各 feature の「完了の定義」に、次を含める: (a) その feature を試行できる状態であること、(b) その feature に必要な構築・設定・マイグレーションが、009 のスクリプトで再現できること。
- FR-27 スクリプトは、feature の追加に合わせて拡張する。拡張しても、既存の環境に対して再実行(アップグレード)できる。
- FR-28 各 feature の試行の開始前に、スモークテストにその feature の確認項目を追加する。

## 受け入れ基準(例)
- 新しい Windows PC で、設定ファイルを用意してスクリプトを実行すると、サーバーまたはランナーが動作する状態になり、スモークテストが通る。
- 同じスクリプトを 2 回実行しても、状態が壊れず、2 回目は変更なしと報告される。
- ドライランでは、システムに変更が加わらない。
- マイグレーションの適用前にバックアップが作られ、失敗時に復元手順が示される。
- ログとコンソール出力に、パスワードやトークンが現れない(テストで検査)。
- 専用アカウントでは、作業フォルダ外のファイル(テスト用のダミー)を読めない。
- スクリプトに、特定の用途の語(機材、評価)が含まれない。

## スコープ外
- 耐障害性(2 台構成、レプリケーション、切替)のスクリプト(feature 008。本 feature の枠組みを使う)
- OS のインストール、PC 自体の準備、評価機材の接続
- アプリケーション機能の実装

- [NEEDS CLARIFICATION] サーバー/ランナーの PC が構築時にインターネットへ接続できるか(できない場合は、別の PC で取得して持ち込む)
- [NEEDS CLARIFICATION] 資格情報の保管機能から、サービスを実行する専用アカウントが読み出す方法(要検証。後述の注意)

## 決定済み
- スクリプトの言語は PowerShell。
- インストーラは公式サイトから取得する。
- 秘密情報は Windows の資格情報の保管機能を使う。
- 試行は、各 feature の実装後に個別に行う。
```
