# /speckit.specify 入力(feature 002: runner-management)

ランナー(機材)と、ジョブの割り当ての管理。「別途詰めたい」領域のため、境界と最小限のみ定義し、不明点は clarify に回す。

## 入力

```
# 機能: コア — ランナーとジョブの管理(最小版)

## 背景と目的
ジョブを実行するランナー(Windows PC 上のエージェント)を登録・管理し、ジョブとの割り当てを管理する。
どのランナーが何をできるか(能力)の記述と、ジョブのランナー要件とのマッチングを提供する。
詳細は別途詰めるため、まず他の feature(001, 004)が必要とする最小の契約を定める。

## ユビキタス言語
- ランナー(Runner): ジョブを 1 つずつ実行する主体。評価機材に接続された PC 上のエージェントに対応する。
- 能力(Capability): ランナーが持つ性質。キーと値の組(例: 機材の種類、ファームウェアの版)。値の意味はコアが解釈しない。
- ランナー要件: ジョブが求める能力の条件(一致・包含・版や数値の比較)。
- 状態: online / offline / maintenance(詳細は clarify で確定)。
- 割り当て(Assignment): ジョブとランナーの対応。リース(一定時間の貸し出し)の形で管理する。

## 最小の要件
- FR-1 管理者は、ランナーを登録・無効化(maintenance)・削除できる。
- FR-2 ランナーは能力の集合を持つ。能力は登録時に設定され、管理者が更新できる。
- FR-3 要件を満たしうるランナーが登録されているかを判定できる(001 の提出時の拒否に使う)。
- FR-4 online で空いているランナーのうち、要件を満たすものにだけ、待機中のジョブを割り当てる。
- FR-5 割り当ては一定時間のリースで管理し、ランナーからの定期的な生存通知で延長される。リースが切れた場合の扱いは feature 004 と別途定める。
- FR-6 ランナーごとに認証情報(トークン)を発行し、失効できる。
- FR-7 ランナーの登録・変更・状態変更は監査ログに残る。

## スコープ外(別途詰める)
- ランナーの自動登録・自動検出、能力の自動取得
- ランナーのメンテナンス運用の詳細(実行中ジョブがあるときの扱いなど)
- ジョブの状態遷移の細則とリース切れの扱い(feature 004 とあわせて定義)

## 未確定事項
- [NEEDS CLARIFICATION] 能力の表現の形式と、要件の記述の文法(比較演算の種類)
- [NEEDS CLARIFICATION] ランナーの状態の種類と遷移
- [NEEDS CLARIFICATION] 能力の登録方法(管理者の手入力/ランナーの自己申告/両方)
- [NEEDS CLARIFICATION] リースの時間と、生存通知の間隔
- [NEEDS CLARIFICATION] 機材の接続状態(機材側の故障)をランナーの状態にどう反映するか
```
