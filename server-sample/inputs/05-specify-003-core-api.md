# /speckit.specify 入力(feature 003: core-api)

## 入力

```
# 機能: コア API — コアを HTTP API として公開する

## 背景と目的
001(ジョブ)・002(ランナー)のコアを、HTTP API として公開する。
WebUI、GitHub 連携、他のクライアント、ランナーエージェントは、この API(とランナープロトコル)だけを使ってコアを利用する。
API は特定の提出元・用途に依存しない。

## ユビキタス言語
- 主体(Principal): API を呼ぶ認証済みの主体。人間の利用者、サービス(連携部品)、ランナーの 3 種類。
- 権限(Permission): 操作の可否の単位。ロールは権限の集合。
- サービス主体: GitHub 連携などの連携部品が使う認証。提出者の代理を許可された権限を持つ。

## 要件
- FR-1 コアの機能(ジョブの提出・参照・優先度変更・割り込み・中断・やり直し、ランナーの管理、監査ログの参照)を HTTP API として公開する。
- FR-2 API は OpenAPI で定義し、バージョンを付ける。破壊的変更はバージョンを上げる。クライアントは OpenAPI から生成できる。
- FR-3 主体は 3 種類を区別して認証する。
  - 人間の利用者: 認証基盤(ポート)が確認した本人性と所属グループから、ロールを決める。
  - サービス: サービス用の認証情報(失効可能)。
  - ランナー: ランナーごとの認証情報(失効可能)。
- FR-4 認可は権限単位で判定する。ロール→権限、所属グループ→ロールの対応は、設定で変更できる。
- FR-5 認証基盤は差し替え可能なポートとして定義する。API 自体は特定の認証基盤の語を含まない。
- FR-6 エラーは、利用者が原因を判断できる機械可読な形式で返す(例: 要件を満たすランナーなし、権限不足、不正な状態遷移)。
- FR-7 一覧は、状態・提出者・期間での絞り込みと、ページ分割ができる。管理者向けにキュー全体の順序つき一覧を提供する。
- FR-8 状態の変更を即時に画面へ反映するため、変更の購読手段(イベントの配信)を提供する。
- FR-9 すべての状態変更の呼び出しは監査ログに記録される(呼び出した主体、代理の場合は代理元も)。
- FR-10 イントラネット内からのみ到達できる。
- FR-11(機密保護)API が外部へ書き出すものは、書き出し台帳(13-security-egress)に載ったものだけとする(GitHub への書き戻し E9、通知 E10 は、状態・短い説明・リンクに限る)。テレメトリは送らない。
- FR-12(機密保護)ランナーから受け取ったログ・成果物は、API の利用者(権限のある者)だけが参照でき、外部の連携先(通知、書き戻し)には本文を渡さない。

## 受け入れ基準(例)
- OpenAPI から生成したクライアントだけで、ジョブの提出・参照・管理が行える(WebUI や GitHub 連携の実装を使わずに)。
- サービス主体が、別の提出者の名義でジョブを提出でき、監査ログに代理元が残る。一般の利用者は代理提出できない。
- 失効したランナーの認証情報では、ジョブを取得できない。
- 偽の認証基盤で、GitHub なしに利用者としてログインして一連の操作を試験できる。

## スコープ外
- ランナーがジョブを取得・実行・報告するためのプロトコル(feature 004 で定義し、本 API が提供する)
- 画面(006)、GitHub 固有の認証(005)

- [NEEDS CLARIFICATION] API のバージョニング方針(URL/ヘッダ)
```
