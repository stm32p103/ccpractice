# 機密保護: 書き出し台帳(Egress Ledger)と対策の骨格

Spec Kit のコマンドへの直接入力ではない。constitution(最重要原則 S1〜S6)・各 specify・plan から参照する。
**台帳にない外部への書き出しは禁止**。書き出しを追加するときは、この台帳を更新し、レビューを受ける。

## 対象と範囲

- 対象: ワーカー(ランナーエージェント、エグゼキュータ、起動した外部ツール)、GitHub Actions のランナー(ワークフロー)。
- 守る情報: 実行 PC 内の、ジョブ用の作業フォルダ**外**の情報(ファイル、環境変数、他のサービスの資格情報・設定、他のジョブの情報)。
- 禁止: 上記を、(a) 外部へ送信すること、(b) Git にコミット/プッシュすること。
- 「外部」: そのプロセスが動く PC の外、および台帳に載っていない送信先すべて。

## 書き出し台帳(初期案)

| # | 送信元 | 出力先 | 書き出す内容 | 条件・制限 |
|---|---|---|---|---|
| E1 | GitHub Actions ワークフロー | 提出ゲートウェイ(イントラ) | 提出契約: リポジトリ、リビジョン、依頼ファイルのパス、OIDC トークン、希望優先度 | 依頼ファイルの中身は送らない(ゲートウェイが取得)。環境変数・Secrets は送らない |
| E2 | GitHub Actions ワークフロー | Actions の実行ログ | 受付結果(受付 ID、拒否理由)のみ | 環境変数・ファイル一覧のダンプ禁止。デバッグログ(ACTIONS_STEP_DEBUG 等)に依存しない |
| E3 | GitHub Actions ワークフロー | Git(コミット/プッシュ)・Actions アーティファクト・キャッシュ | **なし** | 書き出さない。権限は `contents: read` と `id-token: write` のみ |
| E4 | ランナーエージェント | コア API(イントラ) | 能力の登録(clarify で確定した項目のみ)、生存通知、ジョブの状態 | ホスト名・ユーザー名・パス等の PC 情報は、台帳で許可した項目以外は送らない |
| E5 | ランナーエージェント | コア API(イントラ) | ジョブのログ(外部ツールの標準出力/エラー) | 機密パターンはマスク。ログの量を制限 |
| E6 | ランナーエージェント | コア API または保存先(clarify で確定) | 成果物 | 作業フォルダ内の、ジョブ定義で明示した出力パターンに一致するものだけ |
| E7 | ランナーエージェント | ソース取得先(GitHub。取得のみ) | リポジトリ・リビジョンの取得要求、短命の取得資格 | 許可リストのリポジトリのみ。資格は短命・読み取り専用・ジョブ終了で破棄 |
| E8 | 外部ツール(子プロセス) | **なし**(外部通信は許可しない) | — | 外向き通信は Windows ファイアウォールで、エージェント以外のプロセスについて原則遮断(ツールが必要とする通信は、台帳に追加して許可) |
| E9 | コア / GitHub 連携 | GitHub(書き戻し。任意) | リビジョンに対する状態、短い説明、WebUI へのリンク | ログ本文・成果物の中身・ランナー情報を含めない |
| E10 | 通知 | 通知先(メール/Teams 等) | ジョブの状態、結果の要約、WebUI へのリンク | ログ本文・成果物の中身を含めない |
| E11 | WebUI / コア API | **なし**(外部) | — | テレメトリ・解析・外部フォント/CDN の読み込みなし。ブラウザから外部への通信なし |
| E12 | バックアップ(008、009) | バックアップ保管先(clarify で確定) | DB のバックアップ | 保管先と暗号化の有無を明示 |
| E13 | 環境構築スクリプト(009) | 各製品の公式サイト(取得のみ。ドメインは設定で許可リスト固定、HTTPS のみ) | 取得要求のみ | 構築時のみ。版を固定し、公式のハッシュ/署名で検証。環境情報・資格情報は送らない。稼働中は外向き通信を遮断 |
| E14 | 環境構築スクリプト(009) | ローカルのログファイル | 実行の記録 | 外部へ送らない。秘密情報を出力しない。ファイルの ACL を制限 |

[NEEDS CLARIFICATION] E4 で送ってよい PC 情報の範囲、E6 / E12 の保存先、E8 でツールに必要な通信。

## 対策の骨格(plan で実装方法を決め、テストする)

| 層 | 対策 |
|---|---|
| ツール起動 | 環境変数は空から許可リストだけで組み立てる(親の環境を継承しない)。起動は引数配列でシェルを介さない |
| 入力の検証 | payload・依頼ファイル由来のパスは正規化し、作業フォルダ外(`..`、絶対パス、シンボリックリンク、ジャンクション)を拒否 |
| ファイル | 作業フォルダはジョブごとに新規作成し、終了後に消す。収集する成果物はパターン一致のみ |
| 権限 | 専用の低権限アカウントで実行。作業フォルダ以外への読み取りを ACL で与えない |
| ネットワーク | Windows ファイアウォールで、外向き通信を許可先(コア API、ソース取得先)に限定 |
| GitHub | ワークフローは最小権限。Secrets を使わない。コミット/プッシュ/アーティファクトを使わない。書き戻しは定義済みの項目のみ |
| ログ | 送信前に機密パターンをマスク(補助的な対策) |
| 検証 | 台帳の各項目に対応するテスト。「台帳にない送信がない」ことを、送信を記録するテスト用の偽サーバーで確認 |
| 監査 | 作業フォルダ外へのアクセス拒否・マスク発動・書き出しの記録を監査ログに残す |

## 残るリスク(正直な限界)

- 仮想化・コンテナが使えないため、外部ツール自体が悪意を持って(または不具合で)作業フォルダ外を読もうとした場合の防御は、
  OS の権限(専用アカウント、ACL)、ファイアウォール、必要なら Job Object などの制限に頼る。完全な隔離ではない。
- したがって、**実行するツールと、実行を許可するリポジトリを信頼できるものに限る**ことを前提とする(許可リスト)。
- 脅威モデル(誰を信頼し、何から守るか)を、実装前に明文化する。 [NEEDS CLARIFICATION]
