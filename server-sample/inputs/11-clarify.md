# /speckit.clarify 入力

各 feature の specify 後に、対応する観点で実行する。

## 共通(全 feature)

```
次の観点で不明点を質問してください:
- この feature が他のモジュールに公開する契約(API/スキーマ/ポート)は何か。公開契約に、用途固有の語やプラットフォーム固有の語が含まれていないか。
- 憲章の「作らないもの」に該当する要望が含まれていないか。
- 依存規則(コアは他を import しない等)に反する前提がないか。
- 機密保護(憲章 S1〜S6): この feature が外部へ書き出す情報は、すべて書き出し台帳(13-security-egress)にあるか。台帳にない書き出しはないか。
  作業フォルダ外の情報(ファイル、環境変数、他のサービスの情報)に触れうる箇所はないか。
- 脅威モデル: 信頼するもの(ツール、リポジトリ、利用者)と、守る対象(ランナー PC 上の情報)は何か。
```

## 機密保護の追加観点(004 / 005 / 008 で特に確認)

```
- 外部ツールが必要とする環境変数・外向き通信は何か(許可リストの初期値)
- ランナーが登録時に送ってよい PC 情報の範囲
- 成果物・ログの保存先(台帳の E6)、バックアップの保存先と暗号化(E12)
- 専用の低権限アカウントの権限と、作業フォルダ以外への ACL の設定方法
- Windows ファイアウォールでの外向き通信の制限の運用
- 利用者の依頼ファイルが、作業フォルダ外を指すパスや環境変数の参照を含みうる場合の扱い
```

## 001 core-job-queue

```
- 優先度の表現(数値/順序入れ替え/両方)と、割り込みとの関係
- 同一出所・同一リビジョンの重複提出、提出数の上限
- やり直しで引き継ぐ項目と、変更できる項目
- 中断理由の必須性と、中断後の状態
- ジョブ・結果の保持期間
```

## 002 runner-management

```
- 能力の表現と要件の文法(一致・包含・比較)
- ランナーの状態と遷移、メンテナンス時の実行中ジョブの扱い
- 能力の登録方法(手入力/自己申告)
- リースの時間と生存通知の間隔、リース切れ時のジョブの扱い
- 機材の故障をランナーの状態へどう反映するか
```

## 003 core-api

```
- 認証方式と有効期限(人間/サービス/ランナー)
- イベント配信の方式
- API のバージョニング
- エラー形式の項目
```

## 004 runner-agent

```
- リース切れ・再実行・リトライの規則、副作用のあるツールの再実行可否
- ソース(リビジョン)の取得の担当と資格の渡し方
- ログと成果物の保存先、容量、保持期間
- 低権限アカウントの運用と、許可リストの管理方法
```

## 005 github-integration

```
- 依頼ファイルの形式と、ランナー要件の書き方
- ロール反映の間隔
- 提出ワークフローの雛形の配布方法
- GitHub への書き戻しの要否と方法
```

## 006 webui

```
- 画面の技術方針
- 順序入れ替えの操作方法
- 用途固有の表示(payload の見せ方)の差し替え方法
```

## 007 notification

```
- 通知先の種類と連絡先の取得元
- 管理者向け通知の要否
```

## 009 environment-setup

```
- 取得を許可する公式サイトのドメイン一覧と、固定する版・ハッシュの管理方法
- 構築時にサーバー/ランナーの PC がインターネットへ接続できるか
- 資格情報の保管機能を、サービスの専用アカウントから読み出す方法(要検証)
- 対象の Windows の版
- 各 feature の試行に必要な環境の数(サーバー/ランナーの台数)
- マイグレーション時の、実行中ジョブの扱い(待機/中断)
- ランナー登録の流れ(登録コードの発行者と有効期限)
```

## 008 fault-tolerance

```
- RPO/RTO の目標値とその根拠
- 切替の方式(手動/半自動/自動)と判断者
- 利用可能な PC の台数、スペック、設置場所、ネットワーク構成
- バックアップの保管先と復元訓練の頻度
```
