# 版の付け方と移行

## 版の上げ方（成果物の約束事で決める）
| 種類 | いつ | 例 |
|---|---|---|
| メジャー | 必須の成果物や、その形式が変わる | テストケース一覧（test-cases.yaml）を必須にする |
| マイナー | 任意のスキル・観点・題材を足す。古い成果物はそのまま使える | 新しい題材を eval-cases に足す |
| パッチ | 書き方の修正。動きは変えない | SKILL.md の言い回しを直す |

1.0.0 になるまでは試行段階として、マイナーの番号をメジャーの代わりに使います。互換を保った追加（任意の列や手順の追加など）はパッチで扱います。

## 版を出す前の確認
- メジャー（1.0.0 までの間はマイナー）の更新では、評価ケースでの回帰テストを必須にする（AP-D12）。同じケースで前の版と比べ、`summary.md` の結果を CHANGELOG に書く
- パッチは自己テスト（`selftest/run_selftest.py`）が通ればよい
- モデルが変わったときも、回帰テストを回す

## ブランチと版
- 開発中のブランチの体制は変えない。新しい版は、新しく切ったブランチから使う
- 成果物には、作ったときの体制の版（`process_version`）とモデル名を残す
- 古い版の成果物を main に戻すときは、その版の基準で受け入れる（AP-D11）

## 移行手順
メジャー更新には、古い成果物を新しい形にそろえる手順を `migrations/<旧版>-to-<新版>.md`（必要ならスクリプトも）として同梱します。
