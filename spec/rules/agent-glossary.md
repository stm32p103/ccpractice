# エージェント用語集

- 対象: エージェント定義で使う用語
- 対象外: ドメイン駆動設計の用語

## 体制
| 用語 | 意味 |
|---|---|
| 開発者 | エージェントに指示を出す人 |
| メインのエージェント | 利用時の窓口。開発者と直接やり取りし、段階ごとにスキル・コマンド・サブエージェントへ委ねる |
| manager | メインのエージェントが状況把握と次の提案に使うスキル |
| spec-reviewer | G1 の前に要件をレビューするエージェント |
| 実装エージェント | 実装とテスト作成を担当するエージェント。`backend-impl`、`frontend-impl`(未作成) |
| 検証エージェント | 実装を検証するエージェント。`contract-tester`、`impl-reviewer`(未作成) |

## 工程
| 用語 | 意味 |
|---|---|
| 段階 | AGENTS.md のワークフローの 0〜7 |
| ゲート | 開発者の明示的な承認が必要な区切り。G1〜G4、PR |
| 工程の状態 | 機能ごとの進行状況。`docs/backlog.md` の「機能の進捗」に記録し、再開に使う |
| 試行環境 | 開発者が動作を試す環境。ホットリロードが使える |
| 本番環境 | 利用者に提供する環境。スクリプトの実行は開発者のみ |
| 検証用環境 | 本番環境のスクリプトを確認する環境。本番環境とは別 |

## やり取り
| 用語 | 意味 |
|---|---|
| 問い合わせ | エージェントから開発者への質問 |
| 提案 | メインのエージェントが開発者に示す次の作業の案 |
| 未決 | 開発者の決定を待つ事項。`docs/backlog.md` に記録 |
| センシティブなデータ | 外部に送らないデータ。対象は `AGENTS.md` に記載 |

## 成果物
| 用語 | 意味 |
|---|---|
| 成果物 | エージェントが作成し、他のエージェントや開発者に渡すもの |
| 開発構想 | 開発者が提示する、アプリケーションでやりたいこと。`specs/concept/*.md` にまとめる |
| 要件 | ユースケースごとの要求。`specs/NNN-<ユースケース>/spec.md`。ID は `REQ-NNN-xx` |
| 仕様 | 集約ごとの最新の内容。`specs/domain/<集約>.md` |
| ユースケース | 機能の単位。`specs/NNN-<ユースケース>/` |
| レビュー結果 | 検証エージェントによる成果物と仕様の比較結果 |
| テスト結果 | OK/NG のサマリと NG の内容 |
| 分野 | コードと実装の担当範囲。`domain`、`api`、`persistence`、`auth`、`frontend`、`ops`。記号は `<y>` |
| 対象 | 分野内の単位。`domain` では集約。記号は `<z>` |

## 実装
| 用語 | 意味 |
|---|---|
| ハンドラ | コマンド・クエリを受け、処理の手順とトランザクションを担当するコード。`api` 分野が担当 |
| API 契約 | API のメソッド、パス、リクエスト、レスポンス、エラー、必要な権限の取り決め。`contracts/openapi.yaml` が正 |
| クエリ用のインターフェース | クエリのデータ取得の取り決め。定義は `api` 分野、実装は `persistence` 分野 |
| トランザクションのインターフェース | ハンドラがトランザクションを扱う取り決め。定義は `api` 分野、実装は `persistence` 分野 |
| ORM モデル | テーブルに対応する ORM のクラス。ドメインモデルとは別 |
| マッパー | ORM モデルとドメインモデルを変換するコード。`persistence` 分野が担当 |
| セッション | サーバー側で保持するログイン状態。定義は `auth` 分野、保存は `persistence` 分野 |
| Depends | FastAPI のエンドポイントごとの依存の宣言。認可に使う |
| 初期状態の拒否 | 権限の宣言がない API へのアクセスを許可しないこと |
| 初期管理者 | 最初のログインに使う管理者。手順の定義は `auth` 分野、スクリプトへの組み込みは `ops` 分野 |
| CSP | ブラウザの通信先を制限する設定。内容は `frontend` 分野、ヘッダーの付与は `api` 分野 |
| 自己署名証明書 | 外部の認証局を使わず自分で発行する HTTPS の証明書 |
| アプリケーションの組み立て | `main.py` で、ミドルウェアと各分野の実装を接続すること。`api` 分野が担当 |
| `ops` の基盤 | テストの前に必要な準備。`install`、`test-tools` |
| 偽の実装 | テストで実物の代わりに使う実装。リポジトリなどをメモリ上で動かす |
| 不安定 | 再実行で結果が変わる E2E テスト。判定は NG のまま |
