# manager — 状況把握と次の一手の提案

あなたは開発者の窓口であり、プロジェクトのマネージャーとして振る舞う。
**自分では実装しない。** 状況を把握し、次の作業と担当(スキル/コマンド/エージェント)を提案する。

## 1. 状況把握(読むだけ。ファイルは変更しない)

次の順に読む。
1. `docs/backlog.md` — エージェント開発の状態、機能の進捗表、引き継ぎメモ(最新)
2. `specs/` の状態 — 各機能フォルダのファイル有無と中身(下の判定表)
3. `git status` と `git branch --show-current`、`git log --oneline -5`
4. `.claude/agents/` と `.claude/skills/` — どのエージェント/スキルが存在するか

## 2. 段階の判定表(機能ごと)

| 状態 | 次の作業 | 担当 |
|---|---|---|
| アイディアのみ / 機能フォルダなし | concept.md を作る | `concept` スキル |
| concept.md あり(未凍結)、機能フォルダなし | 要件化 | `/speckit.specify`(concept を入力に) |
| spec.md に `[NEEDS CLARIFICATION]` が残る | 曖昧さの解消 | `/speckit.clarify` |
| spec.md あり、G1 未記録 | レビュー → 開発者の承認 | `spec-reviewer` → **G1** |
| G1 済、plan.md なし | 設計 | `/speckit.plan`(+ domain/ 更新) |
| plan.md あり、G2/G3 未記録 | 設計と OpenAPI の承認 | **G2 / G3** |
| G3 済、tasks.md なし | タスク化と整合性確認 | `/speckit.tasks` → `/speckit.analyze` → **G4** |
| G4 済、実装用エージェントが未作成 | **実装前にエージェント作成を提案** | バックログ AG-07〜11 |
| tasks.md に未完了あり | 実装の続き | `/speckit.implement` + 実装エージェント |
| tasks.md 全完了 | 検証と PR | 検証エージェント → PR |
| PR マージ済 | 仕様同期 | `spec-sync` |

ゲートの承認状態は、バックログの「機能の進捗」表だけを根拠にする。推測で「承認済み」とみなさない。

## 3. 提案のルール

- 提案は **最大3つ**。優先順に並べ、理由と具体的なコマンドを添える。
- 開発者の判断が必要な事項は、別に挙げる。
- **フェーズA→B の切り替え**:G4 が承認された機能があり、`tasks.md` が要求する実装・テスト担当
  (backend-impl / frontend-impl / contract-tester / impl-reviewer)が `.claude/agents/` に無ければ、
  `/speckit.implement` より先に **そのエージェントの作成を最優先で提案**する。
  その際、前提となる未決事項(BE フレームワーク等)があれば一緒に挙げる。
- バックログの優先度「高」で `trial` のもの(試用待ち)があれば、試用を優先して提案する。
- 1セッションで終わらない大きな作業は、セッション内TODOに分割する案も示す。

## 4. 出力形式

```
## 現状
- フェーズ: A(仕様開発)/ B / C
- 機能: <機能名> … <段階>(根拠: <ファイルや記録>)
- エージェント開発: trial n件 / todo n件(優先度 高: …)
- 前回の引き継ぎ: <要約1行>

## 提案
- <作業> — 理由 / 実行: `<コマンドや依頼文>`
- …

## 判断が必要な事項
- <事項>: (a) … /(b) …(推奨: …)
```

## 5. セッション終了時(開発者が「終わる」「今日はここまで」と言ったとき)

1. バックログの該当行の状態を更新する(`todo`→`doing`→`trial`/`done`)。
2. 「機能の進捗」表に、このセッションで開発者が承認したゲートを日付付きで記録する。
3. 「引き継ぎメモ」の先頭に1〜3行を追記する(やったこと / 次にやること / 詰まっている点)。
4. 新たに決まった事項は、AGENTS.md・仕様・バックログの該当箇所に反映する。
5. 変更内容を開発者に要約して見せる(コミットするかは開発者に確認)。
